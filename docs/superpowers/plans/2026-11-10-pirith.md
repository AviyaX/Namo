# Pirith (text, chanting and read-along) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> Owner decision 2026-11-10: Roman names come from the fixed table `content/pirith_names_en.json` in plain spelling (the letter-rule transliteration is dropped), and the list order is Maha Mangala, Rathana, Karaniyameththa first, then the book's order; a pirith's number is its position in the list.

**Goal:** Add a second Library topic, Pirith: 39 pirith from pitaka.lk shown phrase by phrase, each with its bundled recording, a highlight that follows the chanting, and plain auto-scroll without sound.

**Architecture:** A build tool turns the already-extracted `content/extracted/pitaka_lk_pirith.json` into a second bundled content file plus 39 recordings; the content repository loads both files into one `Library`. A pirith is a `Reading` with one `Section` whose `Verse`s are the source's blocks, each carrying its ordered phrases; the recording carries one start/end time per block. A pure function maps a playing position to (block, phrase); the reader draws blocks as a new item kind and a small follow controller moves the page.

**Tech Stack:** Flutter 3.47 / Dart 3.13, flutter_riverpod, go_router, just_audio (already present, only behind `ChantPlayer`), Python 3 standard library for the build tool. No new package.

**Spec:** `docs/superpowers/specs/2026-11-10-pirith-design.md` (approved 2026-11-10). Section numbers below ("§8.11") refer to it.

## Global Constraints

- **Text is the source's, phrase for phrase.** Nothing religious is typed, corrected, joined, split or reordered — in the tool, the app or the tests. Tests take their text from the bundled or extracted files, never from a string literal of Pali, Sinhala meaning or English meaning. If something looks wrong, report it; do not change it.
- **Recordings are used byte for byte**: no re-encoding, trimming or joining. Every file under `assets/audio/pirith/` must equal the downloaded original in size and SHA-256.
- **No network at run time.** No outside request; no request for a recording until play is pressed.
- **No sound in tests or checks.** Tests use `FakeChantPlayer` (`test/support/fake_chant_player.dart`); nothing constructs `JustAudioChantPlayer` in a test. Any browser used for checking runs muted.
- **No new dependency.** `just_audio` stays imported only in `lib/audio/chant_player.dart`.
- **Buddha Wandanawa is untouched**: `assets/content/namaskaraya_to_pin_dima.json` byte-identical; its reader, bar, bookmarks, Daily Gatha picks and stored data behave as before. Existing tests may change only where they assumed the Library has one topic, and must keep their meaning.
- **Design system only**: colours, sizes, radii and motion come from `lib/design/` (tokens, `NamoType`, widgets); both themes; `test/quality/design_rules_test.dart` must keep passing with no new allow-list entry unless a reason is written beside it. Motion goes through `NamoMotion.of(context, …)` so reduced-motion gets none.
- **Exact names used across tasks**: category id `cat-pirith`, title `Pirith`, subtitle `පිරිත්`; reading id `pirith-<site id>` (e.g. `pirith-08-mahamangala`); the one section's id `p`; block verse ids `b1`, `b2`, …; content file `assets/content/pirith.json`; recordings `assets/audio/pirith/<site id>.m4a`; picture `assets/pictures/pirith.jpg`.
- **Exact interface words**: `Play chanting`, `Pause chanting`, `Restart chanting`, `Start auto-scroll`, `Pause auto-scroll`, `Resume auto-scroll`, `Follow the chanting`, `Previous pirith`, `Next pirith`, `Chanting position`, `Chanted by Ven. Nauyane Ariyadhamma Thero`, failure message `The recording could not be played.`
- **The app must not look like pitaka.lk's own**: Sources says Namo is not connected with it; none of the site's artwork is used. The words "used with permission" appear nowhere (the owner adds them when the permission is given).
- **Three platforms in step**: nothing platform-specific beyond what the app already uses; `pubspec.yaml` asset entries serve Android, iOS and web alike.
- **Git**: identity is the repository's local one; commit locally, never push; end every commit message with `Co-Authored-By: Claude <noreply@anthropic.com>`. Never stage `source_material/pitaka_lk_pirith/audio/` (the downloaded originals stay out of git).
- **Commands**: Flutter is at `/c/Users/Dell/develop/flutter/bin/flutter` (not on PATH). Python is run as `python -I -X utf8 <script>`. Every task ends with: `flutter analyze` → "No issues found!", `flutter test` → all pass, `python -I -X utf8 tools/build_content.py . --check` → `content file is up to date`, and from Task 1 on `python -I -X utf8 tools/build_pirith.py . --check` → `pirith content is up to date`.

## Review Focus

1. **A long pirith on a small phone** (Mahasamaya: 178 blocks, about 900 phrase rows): opening it and each highlight change must not rebuild or re-lay-out the whole text. → Task 7 test "a place change rebuilds only the blocks it leaves and enters".
2. **Times that overlap, leave gaps or are missing** (Mettanisamsa blocks 3–4 overlap; Alavaka's last block has no time): the highlight must never jump backwards or land on the untimed block. → Task 3 tests on the real data.
3. **The person scrolls or taps while the chanting plays**: following pauses and never resumes by itself; a tap never starts sound. → Task 7 tests.
4. **Chanting and auto-scroll both asked for**: only one runs. → Task 6 tests.
5. **Roman names with marked letters** (ā ṅ ṃ ṭ …) on web: every place a name is drawn must find the glyphs in a bundled font, or the browser fetches a font from the internet. → Task 2 test on the fallback list and Task 8's glyph check over all 39 names.

### Task 3: Where the chanting is — the timing function

**Files:**
- Create: `lib/audio/chant_timing.dart`
- Test: `test/audio/chant_timing_test.dart`

**Interfaces:**
- Consumes: `BlockTime` (Task 2).
- Produces:
  - `class ChantPlace { const ChantPlace(this.block, this.phrase); final int block, phrase; }` (value equality; zero-based indexes).
  - `ChantPlace? placeAt(Duration position, List<BlockTime?> times, List<List<int>> paliLengths)` — `paliLengths[b][p]` is `phrase.pali.length` (UTF-16 units, as the site counts). Rule (spec §4, §8.18):
    1. block = the **last** index whose time is not null and whose `start <= position`; none → `null`.
    2. progress = `(position − start) / (end − start)`, clamped to 0..1 (an `end <= start` counts as progress 1).
    3. target = total Pali length of the block × progress; phrase = the first index whose running length (inclusive) is `>= target`; an empty block gives phrase 0.
  - `List<List<int>> paliLengthsOf(Reading reading)` — one list per verse of the reading's first section.
  - `Duration? blockStart(List<BlockTime?> times, int block)` — null for an untimed block.

- [ ] **Step 1: Write the failing tests**

  - a gap (`[0–5], [8–10]`): at 6 s → block 0, last phrase.
  - an overlap (`[0–5.2], [5.0–9]`): at 5.1 s → block 1.
