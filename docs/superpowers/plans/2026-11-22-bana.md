# Bana Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Bana bottom tab: YouTube dharma talks arranged by topic and monk, numbered series shown as one card with parts in order and resume, played in YouTube's embedded player inside Namo.

**Architecture:** A pure `BanaCatalogue` model parsed from `bana.json` (bundled copy in `assets/bana/`, newer copy fetched once a day from the audio host and kept in the key-value store). Screens: `BanaScreen` (tab root: search, monk chips, topic chips, series cards + bana tiles), `BanaSeriesScreen`, `BanaPlayerScreen` (embedded player behind an injectable builder so tests never start a WebView). A Python tool builds `bana.json` from the owner's draft list.

**Tech Stack:** Flutter 3.47.9, Riverpod 3, go_router 18. New packages: `youtube_player_iframe: ^6.0.4` (Android/iOS WebView, web iframe), `http` (list fetch, web-safe).

**Spec:** `docs/superpowers/specs/2026-11-22-bana-design.md`. Mockup: https://claude.ai/artifact/VqqWCNDmoCCBcSBeqL1zsX

## Global Constraints

- Tab order: Home, Library, **Bana**, Tripitaka, Saved, Settings. `TabIndex`: home 0, library 1, bana 2, tripitaka 3, saved 4, settings 5. Tab label "Bana", icon `Symbols.smart_display_rounded`.
- Routes: `Routes.bana = '/bana'`, `Routes.banaSeries(id) = '/bana/series/$id'`, `Routes.banaPlay(videoId) = '/bana/play/$videoId'`; series and player pages are inside the tab (bar stays), built with `namoPage(key: state.pageKey, …)` like the Tripitaka list.
- List URL: `'$audioBaseUrl/audio/bana/bana.json'`, sent with the app's existing `audioUserAgent` header. Bundled: `assets/bana/bana.json`. Store keys: `bana.list` (last good JSON text), `bana.fetchedAt` (ISO time), `bana.lastPart` (JSON map seriesId → videoId).
- Fetch at most once per 24 h, when the Bana tab is first built; never blocks the list; keep the fetched file only if it parses and its `version` > the current one.
- Copy (exact): offline message "Bana play from YouTube and need an internet connection."; buttons "Try again", "Open in YouTube"; series card kicker "SERIES · {n} PARTS"; "Continue: part {k}"; "Start: part 1"; player kicker "PART {n} OF {m}"; Previous/Next labels "Part {n}"; source line "From YouTube · {channel}"; chip "All monks", topic chip "All"; search hint "Search bana".
- Titles shown are the file's `title` strings verbatim; never edited in code.
- Player: `youtube_player_iframe` controller for the video id with `showFullscreenButton: true`, `strictRelatedVideos: true`, and the privacy-enhanced (`youtube-nocookie`) origin if the package exposes it; no autoplay requirement. Player failure (error event, or no ready within 15 s) → the offline panel. `embeddable == false` → the panel's Open in YouTube only, no player.
- Opening links uses the existing `linkOpenerProvider` (`lib/settings/powered_by.dart`); YouTube watch URL `https://www.youtube.com/watch?v={id}`.
- Theme tokens only (design-rules test); 48-point targets; no overflow at 320×568, fontScale 1.6, both themes; reduced motion respected.
- Git: the project's usual author identity (as in earlier commits); messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never `git add -A`; never push. One flutter command at a time.

## Review Focus

1. **Bad or old list from the host** (malformed JSON, lower `version`, network error) — the shown list stays the stored/bundled one, no error shown. (Task 2 tests.)
2. **Tab indexes shift** — every `TabIndex` use, tips and "pressed again" behaviour still land on the right tab; Tripitaka/Saved/Settings addresses still work. (Task 3 `existing tabs still open by address`.)
3. **Monk then topic filtering** — picking a monk hides topics he has no bana in and resets an unavailable topic to All; a series appears whole under its topic. (Task 3 tests.)
4. **Series edges** — part 1 has no Previous, the last part no Next; resume points at the last opened part across app restarts. (Tasks 2, 4, 5 tests.)
5. **Player cannot load** (offline, error, not embeddable) — the panel with Try again / Open in YouTube shows, never a blank box or crash; tests never create a WebView. (Task 5 tests.)

### Task 1: The list file, its tool, and the model

**Files:** Create `tool/bana/build_bana.py`, `tool/bana/topics.json`, `assets/bana/bana.json` (generated), `lib/bana/bana_catalogue.dart`. Modify `pubspec.yaml` (asset folder). Test `test/bana/bana_catalogue_test.dart`, `test/quality/bana_assets_test.dart`.

**Interfaces — Produces:**
- `bana.json` shape: `{"version":1,"topics":[{"id","si","en"}],"speakers":[{"id","name"}],"channels":[{"id","name","url"}],"series":[{"id","title","speaker","channel","topics":[..],"parts":[videoId,…]}],"bana":[{"id","title","speaker","channel","topics":[..],"seconds":int,"embeddable":bool,"series"?:id,"part"?:int}]}`. Topic ids in order M ME BG SU KS DP PW LV PY DL PT with the spec's Sinhala/English names. Series ids `samatha-bhavana`, `patthana-deshana`. Speaker ids `na-uyane-ariyadhamma`, `kiriwaththuduwe-ariyadassana` (display names as in the spec). Bana in a series carry no topics (`[]`).
- `class BanaCatalogue { final int version; List<BanaTopic> topics; List<BanaSpeaker> speakers; Map<String,BanaChannel> channels; List<BanaSeries> series; List<Bana> bana; static BanaCatalogue? parse(String json); Bana? byId(String id); BanaSeries? seriesById(String id); List<Bana> partsOf(String seriesId); List<BanaItem> filter({String? speakerId, String? topicId, String query = ''}); Set<String> topicsFor(String? speakerId); }`
- `sealed class BanaItem` with `SeriesItem(BanaSeries)` and `SingleItem(Bana)`; filter order: series first (file order), then single bana (file order). A non-empty query matches titles case-insensitively (Sinhala as-is) of single bana and series parts; a matching part is returned as `SingleItem` of that part; series cards are not returned for a query.
- `Bana.watchUri`, `Bana.thumbnailUri` (`https://i.ytimg.com/vi/{id}/mqdefault.jpg`), `Bana.lengthLabel` (`m:ss` / `h:mm:ss`).

- [ ] **Step 1: the tool.** `python tool/bana/build_bana.py tool/bana/draft-list.json tool/bana/topics.json > assets/bana/bana.json`: maps draft topic codes, trims titles only by the known strings listed in `topics.json` under `"trim"` (the channel names, the monks' name forms) plus `|` / ` - ` separators, prints to stderr titles still containing "thero", "uyane" or "ariyadassana" for review, keeps one record per video id, sorts series parts by `part`, uses draft `len` for `seconds`. Run it; commit the output.
- [ ] **Step 2: failing tests** — `parses the bundled file` (180 bana, 2 series with 23 and 72 parts, 11 topics, 2 speakers); `parse returns null on malformed or missing version`; `filter by speaker then topic` (Kiriwaththuduwe → `topicsFor` == {PT}); `a series shows whole under its topic` (PT → the Patthana series card + Na Uyane's single Patthana bana); `query finds a series part` ("ආනාපානසති" → parts 17 and 18 as SingleItems); `partsOf is in part order 1..72`; asset test: every id is 11 characters, every series part exists in `bana`, every topic/speaker/channel id resolves, every title is non-empty and appears inside one of the YouTube titles in `tool/bana/draft-list.json`.
- [ ] **Steps 3–5:** fail, implement, pass + `flutter analyze`. Commit `feat(bana): the bana list, its tool and model`.

### Task 2: Loading and refreshing the list; series progress

**Files:** Create `lib/bana/bana_repository.dart`, `lib/bana/bana_progress.dart`. Modify `pubspec.yaml` (`http`). Test `test/bana/bana_repository_test.dart`, `test/bana/bana_progress_test.dart`.

**Interfaces — Consumes:** Task 1 `BanaCatalogue.parse`. **Produces:**
- `typedef BanaFetch = Future<String?> Function(Uri url);` `final banaFetchProvider = Provider<BanaFetch>` (real: `http.get` with the `audioUserAgent` header, 20 s timeout, null on non-200/error). `final banaClockProvider = Provider<DateTime Function()>`.
- `final banaCatalogueProvider = AsyncNotifierProvider<BanaCatalogueController, BanaCatalogue>`: build = stored `bana.list` if it parses and its version ≥ bundled, else bundled (via `rootBundle`); then, if `bana.fetchedAt` is absent or ≥ 24 h old, fetch in the background, write `bana.fetchedAt`, and if the result parses with a higher version, store it and update state.
- `final banaProgressProvider = NotifierProvider<BanaProgress, Map<String,String>>` with `void opened(Bana b)` (records `b.series → b.id` when in a series, persists to `bana.lastPart`) and `String? lastPart(String seriesId)`.
